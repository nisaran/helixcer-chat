Helixcer Developer API

Connect your apps to the Helixcer inbox.

The Helixcer Messaging API gives external systems one secure path into the shared inbox. Available now: send approved WhatsApp templates from an ERP, CRM, store, or custom app and track Meta delivery on the same conversation.

Available now: WhatsApp template messages. Telegram and Instagram external-send endpoints are not enabled yet. Live WhatsApp delivery requires a valid Meta access token and an approved template whose name, language, components, and parameters match the request.

Quickstart

Send a template from your server

Choose a saved WhatsApp channel, provide the recipient and approved Meta template, then retain the returned Helixcer message ID.

POSThttps://api.chat.helixcer.com/api/v1/whatsapp/template-messages
cURL · simple template
curl --request POST \
  --url https://api.chat.helixcer.com/api/v1/whatsapp/template-messages \
  --header 'Authorization: Bearer hxc_live_REPLACE_WITH_YOUR_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "channelId": "66d66f0c-0ca2-4c79-96b9-d182d5a481b4",
    "to": "919999999999",
    "contact": { "displayName": "Asha" },
    "clientReference": "customer-4082",
    "template": {
      "name": "hello_world",
      "language": { "code": "en_US" }
    }
  }'
1

Select the channel

Use a Helixcer channelId. Credentials stay encrypted on the connection.

2

Send Meta-native data

Name, locale, components, parameter types, and indexes must match the approved template.

3

Track the message

Save messageId. Poll its status or use the inbox and status webhooks.

Authentication

Your key stays on your server

Create a workspace key in Helixcer and include it as a Bearer token. Sending requires whatsapp:template:send; reading status requires messages:read. The key applies to the workspace's WhatsApp connections, and each send selects one with channelId.

A Helixcer key is not a Meta token. External applications never receive the Meta token, WABA ID, or phone-number ID saved on the channel.
Required headers
Authorization: Bearer hxc_live_REPLACE_WITH_YOUR_KEY
Content-Type: application/json

An API key is shown once. Store it in a server-side secret manager or environment variable. Never place it in browser JavaScript, a mobile app, logs, screenshots, support messages, or a source repository. Revoke and replace it immediately if it may have leaked.

Request contract

Send a template message

Helixcer validates the outer envelope, finds the channel's encrypted credentials, renders the approved template for the inbox, records its text and media, and submits a Meta-compatible template payload.

POSThttps://api.chat.helixcer.com/api/v1/whatsapp/template-messages
JSON request body
{
  "channelId": "66d66f0c-0ca2-4c79-96b9-d182d5a481b4",
  "to": "919999999999",
  "contact": { "displayName": "Asha" },
  "clientReference": "order-1001",
  "previewText": "Order ORD-1001 confirmed",
  "template": {
    "name": "order_confirmation",
    "language": { "code": "en_US" },
    "components": [
      {
        "type": "body",
        "parameters": [
          { "type": "text", "text": "Asha" },
          { "type": "text", "text": "ORD-1001" }
        ]
      }
    ]
  }
}
FieldRequiredDescription
channelIdYesHelixcer ID of the saved WhatsApp channel that sends the message.
toYesRecipient's WhatsApp number in international digits-only format, for example 919999999999.
contact.displayNameNoName used to save or update to the contact list
clientReferenceNoYour order, ticket, campaign, or transaction ID. It is stored with and returned on the message.
previewTextNoOptional inbox-text override. When omitted, Helixcer renders the approved Meta template with the supplied variables, media, footer, and action labels.
templateYesMeta-native template object. name and language.code are required; add components when expected.
i

Do not send connection credentials. Meta access token, WABA ID, phone-number ID, Graph version, messaging_product, and recipient_type belong to the selected Helixcer channel.

Template patterns

Use the components Meta approved

Each panel shows the template portion of a request. Add the same top-level channelId, to, contact/reference fields, and required headers shown above.

Simple template with no variables No components

Omit components when the approved template contains no runtime values.

template
"template": {
  "name": "hello_world",
  "language": { "code": "en_US" }
}
Positional and named body variables Body

Positional values map to {{1}}, {{2}}, and so on by array order.

Positional parameters
"components": [
  {
    "type": "body",
    "parameters": [
      { "type": "text", "text": "ORD-1001" },
      { "type": "text", "text": "28 October" }
    ]
  }
]

For named variables, include each approved parameter_name. Do not mix named and positional values in one component.

Named parameters
"components": [
  {
    "type": "body",
    "parameters": [
      {
        "type": "text",
        "parameter_name": "customer_name",
        "text": "Asha"
      },
      {
        "type": "text",
        "parameter_name": "order_number",
        "text": "ORD-1001"
      }
    ]
  }
]
Text header variable Header

Use a header component only when the approved header contains a runtime text variable.

Text header

  },

    "parameters": [

Image, video, and document headers Media

The media type must match the approved header. Supply exactly one source: a public HTTPS link or uploaded Meta media id.

Image · URL
"components": [{
  "type": "header",
  "parameters": [{
    "type": "image",
    "image": {
      "link": "https://cdn.example.com/products/item-1001.jpg"
    }
  }]
}]
Video · media ID
"components": [{
  "type": "header",
  "parameters": [{
    "type": "video",
    "video": { "id": "META_MEDIA_ID" }
  }]
}]
Document · URL
"components": [{
  "type": "header",
  "parameters": [{
    "type": "document",
    "document": {
      "link": "https://cdn.example.com/invoices/INV-1001.pdf",

Currency and date/time parameters Typed values

Use Meta's native typed parameters. amount_1000 is the amount multiplied by 1,000. Always provide a readable fallback.

Currency + date/time
"components": [{
  "type": "body",
  "parameters": [
    {
      "type": "currency",
      "currency": {
        "fallback_value": "INR 1,499.00",
        "code": "INR",
        "amount_1000": 1499000
      }
    },
    {
      "type": "date_time",
      "date_time": {
        "fallback_value": "31 October 2026"
      }
    }
  ]
}]
Static and dynamic call-to-action buttons CTA

Static CTA: When a phone number or URL is fully static in the approved template, omit its button component at send time. Meta renders it automatically.

Dynamic URL: Send only the approved variable value. The index is a zero-based string.

Dynamic URL suffix
"components": [{
  "type": "button",
  "sub_type": "url",
  "index": "0",
  "parameters": [
    { "type": "text", "text": "ORD-1001" }
  ]
}]

For an approved URL ending /orders/{{1}}, this supplies only ORD-1001.

Copy-code and authentication templates Code / OTP

A copy-code button commonly uses a coupon code parameter.

Copy code
"components": [{
  "type": "button",
  "sub_type": "copy_code",
  "index": "0",
  "parameters": [{
    "type": "coupon_code",

Authentication templates can include an OTP, copy-code button, and/or autofill or zero-tap URL. Pass exactly what Meta approved. Never place an OTP in a client reference or log.

Accepted response

Every valid send is asynchronous

Helixcer first records the message and queues provider delivery. Accepted sends therefore return 202 Accepted. The first messageStatus value is normally pending; Meta submission happens just after the response.

i

status reports whether the API request succeeded. messageStatus reports the message's delivery state.

202 Accepted

Stored and queued

The message exists in the inbox and provider delivery is running asynchronously.

GET 200

Current state

The status route returns the latest stored result using the same flat shape.

4xx / 5xx

Request rejected

Read the stable error code and decide whether the request is safe to retry.

Status API

Read the current message state

GEThttps://api.chat.helixcer.com/api/v1/messages/{messageId}

Use the same Bearer key. The key requires the message-read scope and can read only messages it created.

Unified inbox

External sends stay in the conversation

Helixcer resolves the WhatsApp identity, creates a contact and open conversation when needed, and records the outbound template before provider delivery runs.

Your apptemplate request
→
Helixcerrecord in chatbox
→
MetaWhatsApp delivery

Customermessage & reply

Meta sends asynchronous status webhooks to the connected channel. Helixcer applies sent, delivered, read, or failed to the same item. Replies join the same contact and conversation, so agents see the complete thread.

Machine-to-machine status: poll the GET endpoint or use the chatbox today. When Helixcer outbound status webhooks are enabled, consumers should verify signatures, acknowledge quickly, deduplicate event IDs, expect retries and out-of-order events, and reconcile through GET.

Error handling

Stable codes for application logic

Use error.code, not the human-readable message. Include requestId or the matching X-Request-Id response header when contacting support.

Standard error
{
  "status": false,
  "error": {
    "code": "channel_not_ready",
    "message": "The WhatsApp channel is missing its access token.",
    "requestId": "96fe6806-a769-451e-918a-034b33d06dc1"
  }
}
StatusMeaningAction
400Malformed JSON, missing or unknown field, or invalid parameter.Correct the request; do not retry unchanged.
401Missing, invalid, expired, or revoked API key.Replace the key and ensure it is not logged.
403Browser-origin request or key lacks the required scope.Send server-to-server; check key permissions.
404Channel, message, or API route was not found for this key.Check the ID and confirm the channel belongs to the key's workspace.
409The selected channel is not ready to send.Read error.code and fix the channel setup.
429Rate limit exceeded.Wait for Retry-After before trying again.
5xxTemporary Helixcer, rate-limiter, or upstream failure.Wait, then retry with exponential backoff.

Before production

Security and reliability checklist

  • The WhatsApp channel is enabled and has a valid Meta access token and Phone Number ID.
  • The template name, locale, components, indexes, and parameters exactly match Meta's approved template.
  • Recipient numbers use international digits-only format.
  • The API key is stored only on your server and rotated periodically.
  • Your application treats 202 as recorded and queued, not delivered.
  • Retries use exponential backoff.
  • Logs exclude keys, OTPs, sensitive message content, and unnecessary personal data.
  • Status processing safely handles duplicate provider events and can reconcile through the GET endpoint.
